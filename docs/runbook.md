# Сборка и запуск автономного контейнера

Лабораторный образ `repairflow:lab` собирается в две стадии на базе закреплённого по дайджесту образа `python:3.12-slim-bookworm` из `Dockerfile`. На шаге установки пакетов сеть отключена: зависимости берутся только из локального каталога `wheelhouse`, а в финальный слой копируется готовое окружение `/usr/local` без самого склада колёс. На дистрибутивах Astra Linux и РЕД ОС этот контейнер не проверялся.

Каталог `wheelhouse` формируется заданием `wheelhouse` в CI (или локально теми же тремя шагами: загрузка колёс по хешам из `requirements-lock.txt`, сборка колеса ядра SynAPS и сборка колеса RepairFlow).

## Сборка и проверка версии

```text
docker pull python:3.12-slim-bookworm@sha256:34386ef0cb081344d7ec1c103ba398e6e9f64e9ab3a1509accc92a4e24a07258
docker build --pull=false --network none -t repairflow:lab .
docker run --rm --network none --read-only --tmpfs /tmp:rw,mode=1777 repairflow:lab version
```

## Запуск демонстрационного стенда

Команда `demo` записывает выходные файлы в смонтированный каталог, поэтому каталог на хосте должен быть доступен на запись непривилегированному пользователю контейнера (`65534:65534`, `nobody`):

```text
docker run --rm --network none --read-only --tmpfs /tmp:rw,mode=1777 -u 65534:65534 -v /path/to/out:/out repairflow:lab demo --out /out
```

Контейнер запускается с корневой файловой системой только для чтения (`--read-only`), не открывает сетевых портов, не обращается к внешним учётным системам и завершает работу сразу после выполнения переданной команды `repairflow`.
