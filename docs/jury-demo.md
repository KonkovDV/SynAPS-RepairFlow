# Показ для жюри

`repairflow demo` собирает синтетический участок. Это не СВАРЗ. Числа по памяти не зачитывайте. Откройте файл, который написала команда, или таблицу в README, которую собирает `tools/attest.py`.

## Что делает текущая команда

1. **Вход.** `repairflow demo --out out` пишет `out/repair-site-mvp.json`.
2. **FIFO.** Файл `out/fifo.json`. Для готовности это плохой план: нарушения есть, код выхода не успешный. Говорите то, что лежит в файле.
3. **GREED.** `out/greed.json` — кандидат, который уже прошёл проверку. Можно сказать, что график собран по заявленным правилам и нотариус его принял или отверг. Не говорите, что задачу «решил интеллект».
4. **CP-SAT.** На маленьком пресете появляется `out/cpsat.json`, если демо его не пропустило. Называйте прогон точным только когда в этом файле так и написано.
5. **Сбой.** `out/replan.json` и `out/replan-diff.json`. Про замороженную работу говорите только если `broken_frozen_assignments` в разнице пуст. Демо также пишет `out/post-down.json`: пост последнего визита закрыт на этот интервал. Строка готовности должна показать `CALENDAR_BROKEN` на старом плане, `replan_verified=True` и `frozen_moved=0`. Ранняя дыра на плотной линии всё ещё может оставить списочный ремонт частичным.
6. **Испорченный кандидат.** `out/broken.json` — план GREED после намеренной порчи. Проверка готовности требует неуспешный код выхода.
7. **Чужой лист.** Демо пишет `out/shop-plan.csv`: одна операция GREED поставлена на неизвестный пост. `out/shop-verify.json` — доменная проверка без ядра. Готовность требует `claim=rejected` и `verified_feasible` ложь. Русские причины и отсылка к строке листа лежат в `out/shop-reasons.txt`. Чистый цеховой лист был бы `domain_verified`, не `verified`. Отдельный пример пяти ошибок по-прежнему `schemas/templates/five-errors`.
8. **Объяснение.** `out/witness.json` — минимальный по удалению набор идентификаторов операций для одного жёсткого кода испорченного плана. Это не MUS и не MCS.
9. **Журнал.** Демо дописывает `out/decisions.jsonl` по принятому GREED и проверяет цепочку. Строка готовности содержит `decision-log v2`. Отдельно ту же цепочку показывает `repairflow log verify out/decisions.jsonl`. Демо свидетель вершины не пишет: для `repairflow log witness` нужен файл ключа, которого в репозитории нет.

Кампания порчи планов — не шаг демо. Её счётчики лежат в `docs/fault-campaign.json`. Сводка для папки подачи собрана в `docs/submission-facts.md`.

`python tools/pack_submission.py --out out/submission` копирует эту страницу, заявку, матрицу прослеживаемости, страницу неудобных вопросов, границы, сводку, манифест и кампанию в одну папку. Хеши лежат в `PACKET.json`. Команда не пишет новую прозу и не дописывает число результата.

На этой странице нет ни одной цифры-результата. Результаты остаются в выходных файлах и в `docs/evidence-manifest.json`.
